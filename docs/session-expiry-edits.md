# 編集中のログイン期限切れ（UC共通*b・UC-07）

## Context

CanvasやECのAPIが401を返すと、即座に`window.location.replace`でECのログイン画面へ移動していました。
自動保存の途中でECのセッションが切れると、画面上の未保存の編集（配置・輪郭・寸法・写真）が失われました。
UC共通*bは「ログインすると元のステップへ戻る」、UC-07は「編集内容を保持したまま」保存を続けることを求めます。
GardenDocumentの正本はサーバーで、編集中の状態はZustandのメモリだけにあります。

## Decision

- 401は`handleUnauthorized()`へ集約します。編集画面は表示中だけ処理を登録し、未保存の編集
  （`isDirty`、輪郭の描画中、カメラ設定中）がある場合は遷移せず、編集内容をメモリに保持したまま
  「ログインの有効期限が切れました」と「ECに再ログイン」「保存を再試行」を表示します。
  この間は自動保存を止め、同じ401を繰り返し送りません。
- 「ECに再ログイン」は別ウィンドウでECの`/account/login?returnTo=<Canvasのオリジン>/?loginComplete=1`を開きます。
  ECの`safeReturn`はCanvasのオリジンを戻り先として許可しています。
  戻り先の画面はログイン状態を確認してから、同じオリジンの`BroadcastChannel`で編集画面へ完了を知らせ、ウィンドウを閉じます。
  編集画面は通知を受けると保持している編集内容の保存を再実行します。通知が届かない場合も「保存を再試行」で再実行できます。
- 未保存の編集がない画面（庭一覧、保存済みの編集画面、初回表示）は従来どおりECのログインへ移動し、ログイン後に元のURLへ戻ります。
- 403や認証先障害503の扱いは変更しません。

## Alternatives

- localStorage/sessionStorageへ庭データを退避してからログインへ移動する：庭データの正本をブラウザーへ置くことになり、
  写真で容量制限を超えるため採用しません。
- `window.opener.postMessage`で通知する：Cognitoのログイン画面を経由するとopenerが切れる場合があるため、
  openerに依存しない`BroadcastChannel`を使い、ウィンドウは`noopener`で開きます。
- Canvas内にログインフォームを置く：認証はECのセッションに一本化している既存方針（cognito-auth.md）に反するため採用しません。

## Consequences

- ログインの再確認中も編集を続けられます。画面を閉じると未保存の編集は失われるため、離脱警告は維持します。
- E2Eでは保存要求への401を明示的な障害注入とし、ECが行う戻り先への遷移をログイン用ウィンドウで再現して検証します
  （隔離E2Eは明示したデモ認証設定のため）。実Cognitoでの確認は業務受け入れ試験で行います。
