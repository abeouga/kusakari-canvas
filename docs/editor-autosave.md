# 編集画面の整理と非同期自動保存

## Context

植物候補の相談、上部のEC買い物リストへの重複導線、保存ボタンを廃止する。
既存の自動保存は配置objectsの変更のみを対象とし、写真・輪郭・寸法は取りこぼしていた。
また保存中は編集を禁止し、応答のdocumentで無条件に編集中の状態を上書きしていた。

## Decision

- 商品一覧／買い物リストのセグメント内のEC導線を維持する。
  庭名と保存状態の専用バーも廃止し、戻る・庭名・保存状態を既存の表示切替行に統合する。
  通常の保存状態はアイコンとツールチップ、読み上げ用の状態通知で示し、失敗時の警告と再試行は残す。
  上部の固定高と狭い画面での追加行も削減し、空き領域を編集画面へ戻す。
- 有効なGardenDocumentの変更が500ms落ち着いたら全体スナップショットを非同期保存する。
  写真の未確定輪郭、カメラ設定中、配置ドラッグ中は送信しない。
- 保存要求は同時に1件だけ。送信時のimmutable documentと現在値の同一性を比較し、
  保存中に新たな編集があれば編集内容は保持、revisionだけを引き継いで次の保存へ送る。
  保存中も編集を継続できる。通常の保存ボタンはなく、失敗時だけ再試行を表示する。
- アプリ内移動は進行中の保存と追加編集の保存が完了してから行う。
  通信障害・409競合は表示して自動連打を停止し、編集中の値を残す。
  ブラウザーの終了／再読込は完了を保証できないため、未保存時の離脱警告を維持する。

## Alternatives / Consequences

ボタンだけ消す変更では写真や寸法が保存されないため採用しない。
各ポインター移動で送信せず、変更が落ち着いた後にまとめて保存する。
DB形式は変更しない。競合時に他画面のデータを自動で上書きしない。

## Verification plan

実API・専用MySQL・Chromiumで、配置／寸法／写真／輪郭の保存、再表示、
送信中の追加編集、EC移動直前の保存、通信断からの再試行、実際の409を検証する。
遅延は最初のPUT転送を保留する明示的な通信障害注入とし、正常応答は捏造しない。
通常庭は読取専用で3画面幅の変更前後の高さ・可視領域を比較し、画面を目視する。
通常DBと試験前の専用DBのハッシュを比較し、試験で作成した庭と空カートだけを後片付けする。

## 自動保存導入時の検証結果（専用バー統合前）

- 実API・MySQL・Chromiumの専用検証6件が成功。配置の移動・回転・倍率・複製・削除、
  寸法、写真追加・削除、輪郭確定、辺の長さの自動保存と再読込を確認した。
- 未確定の写真輪郭は保存しない。遅延中も編集を受け付け、応答で新しい編集を消さず、
  次の保存が操作なしで完了する。EC移動も最新状態の保存後に行う。
  通信断の再試行と実409での編集保持を確認し、継続的な自動再送が発生しないことを検査した。
- 320〜1528pxの7画面幅で、保存ボタン・相談ボタン・上部の重複EC導線がないこと、
  上部が48px高に収まること、横方向のはみ出しがないことを確認した。
- 通常庭の比較では、1528px幅で写真と商品一覧が各16px高く、1000px幅では各33px高くなった。
  390px幅は上部が111px短くなり、固定高のキャンバス自体は変わらず、
  初期画面で見える写真部分が38.5px増えた。PC・スマートフォン表示は目視確認済み。
- 初回検証で完成イメージの浮動操作が辺入力の適用ボタンに重なる問題を発見し、
  編集ポップアップより背面に配置した。修正後の実クリックと自動保存が成功した。
- lint、対象TypeScript検査、Webビルド成功。既存の大きな配信ファイルの警告は残る。
  旧手動保存前提の関連テストは待機／再試行へ更新したが、全E2Eは実行していない。
- 通常の全16業務テーブルは検証前後で一致。専用DBも試験前データの一致を確認した。
  証跡は `D:/KusakariVerification/editor-autosave-20261019/e2e-final/`。
  通常庭の読取専用の比較は別の `private/` に置き、Gitには含めない。

## 専用バーの統合（追加変更）

庭名と保存状態だけの48px行をなくし、写真／3D切替と同じ行の左側に統合した。
長い庭名は省略し、全文は見出しの名前とツールチップに保持する。
狭い画面では写真／3Dの短いラベルとカメラ操作アイコンを使う。
480px以下のキャンバスの3D操作だけは2行にし、操作同士の重なりを防ぐ。
写真表示は320px画面でも1行に収まる。保存処理とデータ形式は変更しない。

通常庭の読取専用の変更前後比較では、1528px幅で写真領域と商品一覧が各48px高くなった。
1000px幅では写真領域が85px、商品一覧が48px高くなった。
390px幅では専用バー48pxと操作行41pxを削減し、固定高キャンバス内の写真領域が41px増えた。
商品一覧の高さは変わらないが、画面上での開始位置は48px上がった。
比較証跡は `D:/KusakariVerification/editor-toolbar-20261019/private/` に分離する。

追加変更後も専用の実API・MySQL・Chromium検証6件が成功した。
320〜1528pxの7画面幅を写真／3Dの両方で検査し、長い庭名・保存アイコン・各操作の境界が
重ならないこと、サイドパネルの開閉、庭一覧への戻り、自動保存、通信断と409競合の扱いを確認した。
PC・スマートフォンの画面を目視し、lint・対象TypeScript検査・Webビルドも成功した。
ビルドには既存の大きな配信ファイルの警告が残る。全E2Eは実行していない。
通常16業務テーブルと試験前の専用DBデータは変更なし。
今回作成した専用の庭と空カートのみ除去済み。再表示画面・実保存JSON・検証結果は
`D:/KusakariVerification/editor-toolbar-20261019/e2e-final/` に保存した。
