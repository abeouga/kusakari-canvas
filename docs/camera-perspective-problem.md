# カメラ、パース問題

## 実装への反映（2026-10-02）

実寸が分かる地面の長方形4点から撮影カメラを推定し、Three.jsの透視カメラで合成する方式を追加した。庭の多角形輪郭とは別に基準点を設定する。画像中心が主点・正方画素・歪みなしという仮定の下で焦点距離も推定し、推定不能な場合は縦画角を手動指定する。したがって、焦点距離の事前取得がすべての場合に必須というわけではない。

操作、保存形式、制約、検証方法は[写真のカメラ校正](photo-camera-calibration.md)を参照。以下は問題整理時点の記録。実写精度は実際の庭写真を使った追加確認が必要。

## 問題

写真と3D庭を重ねたとき、木の見た目が写真の奥行きと合わない。実際の庭では、カメラから遠いものほど小さく写る。一方、3D庭で適切に配置した木を写真へ重ねても、奥の木が大きく見えるなど、写真のパースと一致しないことがある。

木の傾きだけを直しても、奥行きに応じた大きさの変化が正しくならなければ、合成結果は不自然なままになる。

## 現状の仕組みと制約

- 写真上に描いた庭の輪郭から外接矩形を作り、その範囲を庭の幅・奥行きへ対応させている。
- この輪郭は地面の形を指定するためのもので、写真上の点と実寸の3D位置との対応を十分に与えていない。
- 写真には撮影カメラの位置・向き、焦点距離、レンズ歪みが分からない場合がある。
- そのため、庭の輪郭をなぞった情報だけから、実際のカメラを一意に復元することはできない。
- 木を垂直に見せる処理と、写真に正しい奥行きの遠近感を与える処理は別の条件である。前者だけでは後者を満たさない。

## カメラを逆算できる条件

カメラの位置・向きは推定できる。ただし、写真上の点と、庭の実寸座標上の点との対応が必要になる。加えて、焦点距離などのカメラ内部情報が必要である。

平面上の対応点からカメラ姿勢を推定する方法がある。OpenCVの資料では、平面ホモグラフィから姿勢を求める場合、カメラ内部情報が既知であることを前提としている。`solvePnP` は既知の3D点、その画像上の位置、カメラ内部情報からカメラに対する姿勢を推定する。

- [OpenCV: 平面ホモグラフィからの姿勢推定](https://docs.opencv.org/4.0.0/d9/dab/tutorial_homography.html)
- [OpenCV: Perspective-n-Pointによる姿勢推定](https://docs.opencv.org/4.12.0/d5/d1f/calib3d_solvePnP.html)
- [OpenCV: カメラ校正とレンズ歪み](https://docs.opencv.org/4.12.0/dc/dbb/tutorial_py_calibration.html)

## 推奨する方法

任意形状の庭輪郭とは別に、写真と実寸を結び付ける「カメラ合わせ用の基準点」を指定する。基準点は、庭の地面上で実寸位置が分かる点にする。庭が長方形とみなせる場合は、地面の四隅と庭の幅・奥行きを対応させる方法が使える。長方形でない場合は、実寸座標を把握できる点を複数指定する。

1. 写真上で、実寸位置が分かる地面の基準点を4点以上指定する。
2. 対応する庭の3D座標と、庭の幅・奥行きを設定する。
3. 写真の焦点距離を使い、カメラの位置・向きを推定する。焦点距離が不明なら、写真メタデータを初期値として、画面上で調整できるようにする。
4. 推定したカメラで木を通常の3D投影で描き、地面上の基準点と木の根元位置が写真に合うか確認する。
5. 写真上の重なりを確認しながら、必要に応じてカメラ設定を微調整する。

同じカメラで全ての3Dモデルを描画すれば、木ごとのサイズを個別に調整せずに、奥行きに応じた縮小を表現できる。基準点、焦点距離、推定したカメラ設定は、庭の編集内容とともに保存する必要がある。

## 方法の比較

| 方法 | 利点 | 制約 |
| --- | --- | --- |
| 輪郭だけから自動推定 | 操作が少ない | 実寸位置とカメラ内部情報が足りず、推定が不安定または不可能 |
| 実寸基準点と焦点距離から推定 | 透視投影とカメラ姿勢を幾何的に合わせられる | 基準点の入力と焦点距離の確認が必要 |
| 手動スライダーだけで調整 | 実装と操作を始めやすい | 見た目合わせになり、実寸位置の精度は保証できない |
| 撮影時にAR姿勢を記録 | カメラ姿勢を撮影時点で取得できる | 写真を撮る機能とARトラッキングが必要。既存の写真アップロードだけでは利用できない |

スマートフォン内で撮影と庭木配置を続けて行う機能へ発展させる場合は、ARCoreなどから撮影時のカメラ姿勢・内部情報を取得する方法が候補になる。ARCoreはカメラの姿勢、内部情報、投影行列を提供する。

- [Google ARCore: Camera](https://developers.google.com/ar/reference/java/com/google/ar/core/Camera)
- [Google ARCore: CameraIntrinsics](https://developers.google.com/ar/reference/java/com/google/ar/core/CameraIntrinsics)

## 結論

現在の写真アップロード方式には、**実寸の地面基準点と焦点距離を使ったカメラ推定に、画面上の手動調整を加える方法**が適している。庭の輪郭を描く操作とカメラ校正を分けることで、地面の形状指定を保ちながら、木の垂直方向と奥行きに応じた遠近感を同じカメラ投影で再現できる。

輪郭だけから実カメラを正確に復元できるとは扱わない。撮影カメラの位置や焦点距離が得られない写真では、手動調整を含む近似として扱う。
