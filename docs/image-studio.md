# 完成イメージとAI画像生成

AI画像生成の現在の仕様です。評価・試行の記録は [kusakari-document の AI画像生成](https://github.com/abeouga/kusakari-document/tree/main/開発の記録/kusakari-canvas/AI画像生成) にあります。

## Context

利用者は、写真に配置した商品が庭でどう見えるかを確かめたい。生成画像は元写真の全景を保ち、解像度を落とさずに保存・比較できる必要がある。生成の操作は作業面を狭めず、説明文や商品一覧を並べない簡素な画面にする。

## Decision

### 入口

- 表示領域右下に1つのボタンだけを置く。写真＋設計では「AI生成」、写真を使わない3D表示では「完成イメージ」と表記する。クリックで「新しく作成」「生成履歴」の小さなメニューを開く。外側クリック・Escape・Tabで閉じ、フォーカスを戻す。輪郭の描画中はボタンを出さない。
- 3D表示の「新しく作成」は、現在の視点の3Dプレビューを表示し、PNGで保存できる。AIは呼ばない。

### 生成

- 写真＋設計の「新しく作成」は、撮影したBefore画像を中心に、生成の主操作を表示する。配置した商品の参考画像（ECの登録画像）は裏側で自動取得し、商品の一覧は通常表示しない。登録画像が使えない商品がある場合だけ、その植物の写真を選ぶ欄を出す。入力画像は最大16枚。
- 入力画像数・生成方式・モデル・品質は閉じた「詳細」にまとめる。OpenAIへの画像送信とAPI利用料は実行ボタン付近に短く表示する。
- `POST /api/gardens/{id}/ai-image` で生成する。新規生成は `full_frame_v3` で、検証済みの生成PNGを元バイト列・生成解像度のまま返却・保存・取得する。API入力の全景変換と座標・マスクの倍率対応は行い、保存時の縮小・切り出しは行わない。生成レスポンスと履歴の `width` / `height` はAfter実画像の寸法、Before寸法は撮影済み `document.photo.imageWidth` / `imageHeight` が正本。
- 生成指示は `ai_prompt.py`（`scene_layout_v1`）が既定で、`ai_prompt_v2.py`（`scene_layout_v2`）は明示した評価用の設定でだけ使う。モデル・品質の既定は `ai_config.py` にある。
- 遮蔽補助画像は生成・表示・API送信しない。入力はBefore画像1枚と商品ごとの植物参考画像に限る。配置の座標情報は投影範囲として送り、可視状態を推定するための植物別撮影は行わない。
- 生成結果はサーバーが生成履歴へ保存する。保存に失敗した場合は画像を画面に保持し、「履歴へ再保存」（生成料金はかからない）か破棄を選べる。未保存の画像を閉じるときは破棄の確認を出す。二重実行を防ぐ。
- OpenAIのAPIキーが未設定のときは接続設定が未完了と表示し、生成しない。

### 生成履歴

- `GET/POST /api/gardens/{id}/image-history`、`GET/DELETE /api/gardens/{id}/image-history/{historyId}` で、庭の所有者だけが一覧・保存・取得・削除できる。一覧はページングする。
- 履歴はAfterのサムネイルカードをPCで3列、スマートフォンで2列表示する。カードには日時だけを表示し、生成方法などは比較画面の閉じた詳細欄に残す。一覧と比較表示を切り替え、戻る操作では選んだカードへフォーカスを戻す。
- サムネイルは `GET /api/gardens/{id}/image-history/{historyId}/thumbnail` で、所有者確認と庭・履歴の対応確認を経てAfterだけを読み、640×400px以内へ縮小する。縦横比を保ち、表示もcontainを使う。一覧メタデータに元画像を埋め込まず、ブラウザーの遅延読み込みを使う。画像は private, no-cache で返す。
- 画像を選択したときだけ元画像と撮影情報を取得する。PNG保存は元のバイト列を維持する。サムネイルの取得失敗はカード単位で再試行でき、比較や他カードを妨げない。履歴削除は確認ダイアログを通し、失敗時は再試行するまで履歴を残す。
- 比較枠はBeforeの縦横比、各画像はcontainで全体を表示する。

## Alternatives

- 低解像度への再縮小と、見栄えのための cover/crop は使用しない。
- 全履歴のフルサイズ画像を詳細APIから先読みする方式は転送・メモリ負荷が大きいため採用しない。サムネイル列のDB追加も行わず、既存画像から読み取り時に縮小する。

## Consequences

撮影画像より生成画像が大きくても表示枠は変わらない。保存容量は増えるが、After画像の20MB上限を維持する。旧方式（`full_frame_v3` より前）の履歴はBefore/After同寸法の検証を維持し、既存履歴・ハッシュを変更しない。旧Afterの欠落画素は復元しない。縦長・横長画像のカードには余白が付く。AIの構図・植物の再現性を保証するものではない。

## 検証

E2Eは `e2e/ai-image.spec.ts`、`e2e/history-gallery.spec.ts`、`e2e/image-history.spec.ts`、`e2e/before-image.spec.ts`、`e2e/before-after-resolution.spec.ts` にある。有料の生成を呼ぶ `e2e/ai-image-live.spec.ts` などは明示した実行条件のときだけ動く。画像変換の独立検証は `backend/verification/verify_ai_frame.py`・`verify_ai_images.py` で行う。評価用写真のライセンスは `e2e/fixtures/ai-quality/README.md` にある。
