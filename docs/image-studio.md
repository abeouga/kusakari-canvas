# 完成イメージの簡素化と生成解像度の保持（2026-10-19）

## Context

利用者の追加要件は「元写真の低解像度へ戻す必要はなく、全景を保つこと」と、
説明文・商品一覧を並べた生成ダイアログの簡素化である。
前の修正で左上切り出しは廃止したが、出力全体を元写真の寸法へ縮小していた。

## Decision

- 新規生成を `full_frame_v3` とし、検証済みの生成PNGを元バイト列・生成解像度のまま返却・保存・取得する。
  API入力の全景変換と座標・マスクの倍率対応は維持し、保存時の縮小・切り出しは行わない。
- 生成レスポンスと履歴の `width` / `height` はAfter実画像の寸法とする。
  Before寸法は撮影済み `document.photo.imageWidth` / `imageHeight` が正本。
  旧方式はBefore/After同寸法の検証を維持し、既存履歴・ハッシュを変更しない。
  DB列追加は不要。比較枠はBeforeの縦横比、各画像はcontainで全体を表示する。
- 入口をキャンバス右下の完成イメージ・履歴の操作エリアへ移す。
  生成前はプレビューと主操作を中心とし、商品参照は裏側で自動取得する。
  商品の一覧は通常表示しない。登録画像が使えない場合に必要な写真入力だけを表示する。
- 入力画像数と生成方式は閉じた「詳細」にまとめる。
  OpenAIへの画像送信・API利用料は実行ボタン付近に短く表示する。
  二重実行防止、保存失敗時の保持・再保存、破棄確認、キーボード操作は維持する。
- 遮蔽補助画像は生成・表示・API送信しない。入力はBefore画像1枚と商品ごとの植物参考画像に限定する。
  配置の座標情報は投影範囲として送り、可視状態を推定するための植物別撮影は行わない。

## Alternatives / Consequences

低解像度への再縮小と、見栄えのためのcover/cropは使用しない。
撮影画像より生成画像が大きくても表示枠は変わらない。保存容量は増えるが既存の20MB上限を維持する。
旧Afterの欠落画素は復元しない。AIの構図・植物の再現性の保証とは別の変更である。

## Verification plan

実API・専用MySQL・Chromiumで、小さいBeforeと大きいAfterの保存、再読込、ダウンロードの
バイト一致、共通表示枠、モバイル表示を検証する。通常データと試験前から存在する専用DBデータを保持する。
画像変換の独立検証は `before-after-resolution.md` の理由を引き継ぎ、切り出しも縮小もされない条件へ更新する。
実商品の自動参照・通信エラーと再試行・連打抑止は実サーバーの無課金エラー応答で検査する。
正常系APIをモックせず、有料の画像生成や生成品質の評価は行わない。
