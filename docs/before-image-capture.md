# Before画像の撮影（フェーズ1）

2026-10-19に遮蔽補助画像は廃止しました。現在はBefore画像とAI編集領域だけを撮影します。以下はフェーズ1の実装記録です。

## Context

AI画像合成の入力には、庭写真と全配置3Dを重ねた一枚を使います。庭写真を画角の基準とし、撮影時の選択枠・変形ハンドル・写真上の編集用グリッドを含めません。

従来の撮影処理は、DOMからWebGL canvasを探し、windowイベントで描画した画像を写真サイズへ拡大していました。撮影ボタン側で選択を解除し、描画待ち後に選択を戻していました。

## Decision

- 写真＋設計モードでは、写真の元の幅・高さを出力寸法とし、現在の写真用カメラの投影を使って直接描画します。SVGに表示される地面・グリッド・寸法・輪郭は合成しません。
- EditorPageが撮影用refを持ち、表示中の3Dコンポーネントが撮影関数を登録します。DOM検索とwindowイベントは使いません。
- `three/SceneCapture.jsx`は描画コンテキストとrefをつなぎます。`three/renderCapture.js`は同期描画と描画状態の復元、`capture/captureImage.js`は写真の読み込みと画像合成、`components/CompletionImageAction.jsx`は撮影操作とプレビューを担当します。
- 写真の読み込みを待つ前に3D画像を同期取得し、撮影開始時の写真参照・寸法と組み合わせます。選択状態とGardenDocumentは変更しません。
- 撮影時だけrendererの画素比を1、描画サイズを出力寸法にします。2D canvasへコピーした後、`finally`で可視状態・元の描画サイズ・画素比・viewport・scissor・render target等を復元して通常表示を描画します。CSSサイズとカメラの投影は変更しません。
- 描画ノードの`captureRole`を使い、編集用表示を除外します。写真モードの全配置は常時マウントし、「配置」表示チェックがOFFでも撮影には含めます。撮影後の表示チェックと可視状態は元のままです。
- 読み込み中・読み込み失敗・不明なモデルは撮影エラーにします。非表示の配置も含めて検査し、仮表示をBefore画像として採用しません。
- GPUの描画可能寸法を超える写真、要求寸法を確保できない描画バッファ、WebGLコンテキスト喪失はエラーにします。寸法を黙って縮小しません。
- 3D庭モードは従来の3Dプレビューとして撮影します。写真付きの庭でも3Dモードの画像は固定写真カメラのBeforeとして扱いません。

## Alternatives

- 画面上の描画画像の拡大：元写真の解像度に対して3Dだけが低解像度になるため不採用です。
- WebGLRenderTargetでの撮影：現在のThree.jsでは通常画面とtone mappingの適用条件が異なります。同じ色調を保つため、今回は通常の描画先を同期的に変更して復元します。
- 別のWebGLRendererでの撮影：追加コンテキストとGPUリソースの管理が必要となるため、既存rendererを使います。
- 編集ストアの選択解除：撮影のために編集状態を変更する必要がないため不採用です。

## Consequences

- フェーズ1ではPNGのプレビューと手動ダウンロードまででした。OpenAI通信、商品画像の参照、DB履歴、Before／Afterスライダーは後続フェーズで追加されています。
- 内部の透明な3D描画は写真合成用の作業canvasです。API送信や3D単体画像の保存は行いません。
- 検証は専用の庭と合成したテスト用写真を使い、実利用者の写真はログ・Git・テスト成果物に含めません。
- Chromium・実API・MySQLによるE2Eで、縦横写真、写真カメラと旧投影、全配置の包含、選択・表示チェックの保持、画面幅変更、再読み込みを確認します。PNGの圧縮バイトではなく復号した画素を比較します。同じ描画コンテキスト内は全画素の完全一致を要求します。
- 再読み込み後は寸法、写真との差分で求めた植物領域、DB JSONの完全一致を要求し、植物領域のRGB二乗平均平方根誤差を8-bit階調の0.5以下に制限します。初回の厳密比較では1200×800中の植物内部1画素のみRGBが変わり（最大成分差10）、植物領域・背景・alphaの差はありませんでした。原因は未確定です。輪郭の一致だけで色の退行を見逃さないよう、色の誤差にも上限を設けています。診断画像と値は`artifacts/phase1-reload-diagnostics/`に残します。
- 3Dコピー処理の例外とGLB通信失敗を明示的に注入し、失敗後の表示復元と再試行を検証します。通常のAPIはモックしません。
