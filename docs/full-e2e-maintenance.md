# 全E2Eの実行環境と現行UIへの更新

## Context

Canvas単独の標準設定ではECを起動せず、ECを必要とするテストにも適用されていた。専用設定には旧リポジトリ名、固定ポート、機械固有のDドライブが残っていた。さらに旧デモ商品、旧AI商品選択フォーム、画像出力の旧導線、未追跡の過去成果物に依存するケースがあった。

`asset-*`ボタンは現行ProductBrowserにも存在する。商品が取得できない場合や廃止済みデモ商品では表示されないため、ボタンそのものの廃止とは区別する。

## Decision

- 全体検証は`npm run test:e2e -- --config e2e/configs/playwright.full.config.ts`で実行する。
- Canvas API/Web、EC API/Webに4つの空きポートを割り当てる。MySQLはCanvasの`kusakari_canvas_e2e`とECの`kusakari_e2e`を使用する。既存開発プロセスの停止・再利用はしない。
- JavaのWindowsソケット用一時ディレクトリをテスト出力配下に限定する。通常の`java.io.tmpdir`より`TEMP`が優先されるため、`jdk.net.unixdomain.tmpdir`を設定する。[OpenJDK実装](https://raw.githubusercontent.com/openjdk/jdk21u/master/src/java.base/windows/classes/sun/nio/ch/UnixDomainSocketsUtil.java)
- 有料AI生成とDB障害注入は既存の明示実行条件を維持する。通常検証では生成キーを空にし、実APIでの未設定応答を確認する。正常系APIモックは追加しない。
- 商品配置には実EC APIで新規作成した商品を使う。廃止済み商品を再有効化しない。旧固定モデルの読み込み・回転・GLB失敗回復には、実Canvas APIで独立した保存済み庭を用意する。
- 過去のテストデータを名前で検索して削除する処理は除去する。
- 画像正規化fixtureは既存Python検証から毎回生成し、機械固有の過去成果物を要求しない。固定入力比較も今回の実ブラウザ送信を保存してから再送と比較し、変更入力の拒否を確認する。

## Alternatives

- 正常系APIのモックや廃止済みデモ商品への依存は、実API/MySQLの検証にならないため採用しない。
- スクリーンショットの差分許容を増やしてフォーカス枠の差を吸収する方法は採用しない。重なるHTMLも撮影されるため、前後のフォーカスを同じチェックボックスにそろえる。

## Consequences

テスト用商品・庭は各ケースで独立作成する。既存データの全消去は行わない。画像出力前後の画素比較、正常系の保存・復元、失敗時の編集保持と再試行を維持する。実行結果は`artifacts/e2e/full-suite/`に保存する。

- 画像関連の追加診断: 商品fixtureの旧DTO項目、旧導線、フォーカス枠の画素差を確認。修正後の全件実行で再検証する。

- `image-studio.md`の承認済み仕様では植物別の遮蔽解析は廃止済み。旧`raster`期待値は、`projected_box`・可視状態未推定・投影範囲への実植物画素の包含検証に置き換える。

- 有料OpenAI生成とDB障害注入の2件は既存の明示実行条件によりスキップし、品質評価・有料経路の成功は主張しない。通常検証のOpenAI呼び出しは0回。

## 標準E2E起動設定の修正（2026-10-20）

- 標準の `npm run test:e2e` はEC接続先を割り当ててもCanvasだけを起動していた。商品fixtureを利用するテストの接続先と起動サービスが一致していなかった。
- `scripts/e2e.mjs` は設定指定がない場合に `e2e/configs/playwright.full.config.ts` を選択する。ファイル指定・grepによる部分実行も同じ4サービスを使用する。明示された `--config` / `--config=...` / `-c` / `-c=...` は優先し、従来の専用設定を上書きしない。
- READMEにECリポジトリ・専用DBの前提、部分実行、成果物の保存先を追記した。Canvas単独設定と一時MySQL検証の対象範囲も明示した。
- `node --check scripts/e2e.mjs`、対象ファイルのESLint、`git diff --check` が成功。標準 `--list` で87件を検出し、`--config=...` と `-c` による対象1件の一覧取得も成功した。
- 設定指定なしの `npm run test:e2e -- e2e/editor-toolbar.spec.ts --output artifacts/e2e/startup-config-20261020/test-results --reporter=line,json` が **1件成功（1.1分）**。実API・専用MySQL・Chromiumで実商品の配置・保存・再読み込みとECへの遷移要求を検証した。JSONレポートは `PLAYWRIGHT_JSON_OUTPUT_FILE` により同ディレクトリの `results.json` へ保存した。再読み込み画像・API JSONも同ディレクトリへ複写した。
- 全E2Eは再実行していない。アプリ実装・依存・DBスキーマは変更していない。

## 2026-11-12 全 E2E の失敗17件の修正と、購入者・出店者のテストアカウントの分離（#69・#64）

### Context

EC の新しい DB 構成（v3）への追従（#68）のあと、全 E2E のうち17件が、画面や準備コードの変更に追従しておらず失敗していた（#69）。
また、店舗側のアカウントは Canvas を使えなくした（#64）。全 E2E は店舗1の MANAGER の担当者（`SHOP_STAFF`）で Canvas を操作していたので、そのままでは全件が 403 になる。

### Decision

- テストアカウントを2つに分ける。画面・Canvas API・カート・買い物リストは購入者 `test.user@example.com`（EC の E2E 用 DB で `USER` にする）。テスト用商品の登録・変更・削除と出店者の商品登録画面は、出店者 `test.seller@example.com`（店舗1の MANAGER の担当者）。試験では `seller`（API）と `sellerPage`（画面）の fixture で出店者を使う（`e2e/test.ts`・`e2e/seller-session.ts`）。
- 商品番号（4件）：EC の新規登録は商品番号をサーバーが採番する。入力をやめ、保存結果の `sku` がサーバーの形式（`KS-年月日-`）であることを確かめる。あわせて、EC の商品登録が4段階（商品情報・画像・庭オブジェクト・確認）になり、植物の高さを庭オブジェクトの段階で入れ、プレビューがボタンなしで更新され、細かい調整が「自動・手動」の切り替えになったことに、`e2e/seller-wizard.ts` と4件の試験を合わせた。
- ツールバーと案内（8件のうち試験の修正）：庭の名前の隣のボタンは「← 庭一覧」と「庭の名前を変更」の2つ。エラーの案内は `.editor-alert.notice-error` で選ぶ（写真が必須の案内は `role="status"` の別の案内）。配置済みの一覧は「商品一覧」のタブにある。
- ツールバー（画面の修正）：幅 320px で庭の名前の幅が 0 になり、名前が見えなかった（名前を変更するボタンが加わったため）。幅 420px 以下では表示モードのボタンを絵だけにして、名前が読めるようにした（`commerce.css`）。
- 輪郭の頂点のエラー（画面の修正）：頂点を成立しない位置へ動かしたときのエラーが写真の上に差し込まれ、写真が下にずれて、次のドラッグが頂点をつかめなかった。エラーを写真の上に重ねて表示し、写真がずれないようにした（`PhotoOverlay.jsx`・`photo.css`）。
- 配置範囲の準備スクリプト（2件）：`placement_fixture.py` に `--owner` を足し、試験はログインした購入者の会員 ID を渡す。持ち主が違う庭は今までどおり拒否する。
- 共通ヘッダー（1件）：ログインした購入者として、「アカウント」があり、「ログイン」「出店者」「管理者画面」がないことを確かめる。
- Before 画像（1件、縦長の旧形式）：原因を調べた。操作をはさまずに続けて2回撮った画面でも、約200の値が1段階だけ違う。違うのは、透明な WebGL のキャンバスの下にある写真（SVG の画像）の文字の部分だけで、Chromium が縮小した写真の描き方を2通りで揺らしている。完成イメージの画像（WebGL の出力）は別に厳密に比べているので、この画面の比較だけ1段階の差を許す。
- 買い物リストの「購入商品を選ぶ」（1件）：EC の画面を直す方針（EC 側で対応）。Canvas の試験は変えない。

### Alternatives

- 1つのアカウントの種別を試験の途中で切り替える案は採用しない。全件が同じアカウントを使うので、途中で失敗すると後の試験が別の種別で動くため。
- Before 画像の比較から写真を隠す案は採用しない。画面に見えているものを比べる、という試験の目的から外れるため。

### Consequences

全 E2E は2つのテストアカウントでログインし、終了時に両方をログアウトする。`e2e/buyer-only.spec.ts` は、出店者のテストアカウントの種別を変えて Canvas の案内と 403 を確かめ、終わったら元の種別と店舗1の持ち主に戻す。
