# 土台の辺の長さの編集

> 更新：多角形の各辺は写真上でクリックして実寸を入力する。全辺の入力で輪郭を固定したまま写真のパースを求め、ほかの辺の値は変更しない。サイドバーの寸法欄は撤去し、写真のない矩形のみ3D画面上部の「土台設定」へ移動した。現行の多角形仕様は[写真上の辺の計測](polygon-edge-editing.md)を参照。以下の幅・奥行きの検証・保存規約は矩形の土台設定に継続適用する。

## Context

新規作成は名前だけにし、実寸を編集画面から変更する要望に対応する。以前は幅・奥行きが作成後不変だった。

## Decision

- 新規作成フォームの入力は名前のみ。POSTで寸法を省略するとAPIが幅10m・奥行き8mを設定する。寸法付きの既存API利用は引き続き受け付ける。
- 写真のない矩形は3D画面上部の「土台設定」からダイアログを開く。各辺1〜50m。「土台に適用」で編集中のGardenDocumentへ反映する。ダイアログを閉じ、上部の「保存」で確定する。Escで閉じたとき、未適用の入力は破棄するが適用済みの寸法は維持する。
- 原点を中心に外枠を変更し、配置物のID・位置・回転・倍率を維持する。配置基準点が範囲外になる縮小を拒否する。
- 校正済み写真の基準長方形の実測値と撮影カメラは維持する。校正済みの輪郭が実寸範囲を超える縮小も拒否する。写真の基準長方形の実寸はカメラ設定側で編集する。
- 旧方式の未校正写真では幅・奥行きが写真輪郭との変換倍率にも影響する。
- 保存中、3D変形中、写真の輪郭描画中、カメラ設定中は寸法を変更できない。
- PUTで寸法不変の制約を廃止し、既存の範囲・写真・配置物検証とrevision照合後、寸法を同じMySQLトランザクションで保存する。DTO・DBの寸法列は既存のものを使用するため、マイグレーションは不要。

## Alternatives

縮小時に配置物を自動移動・拡縮すると、既存の設計を意図せず変えるため採用しない。新規作成の入力欄を残す方式は今回の操作要望に合わない。

## Consequences

寸法変更は既存の庭にも適用可能。幅・奥行きは土台の外枠の長さであり、多角形の各辺を個別に伸縮する機能ではない。入力中の値は「土台に適用」まで保存対象にならず、未適用であることを表示する。

重点E2E `garden-dimensions.spec.ts` で名前のみの作成、初期値、寸法変更、物体を含む縮小の拒否、実API/MySQLの保存・再読込・一覧反映を確認する。成功時には庭JSONと画面を `artifacts/e2e` に保存する。
