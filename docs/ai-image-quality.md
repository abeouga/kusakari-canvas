# フェーズ5：生成品質・統合評価

> 2026-10-16：全画像採用方式の実評価は[新フェーズ4の評価記録](full-frame-quality-phase4.md)を参照してください。動作検証は成功しましたが、拡大・家具消失により品質未達です。以下は旧方式の記録です。

> 2026-10-14追記：利用者は生成後の貼り戻しを廃止し、AIの返却画像全体をAfterへ採用する方式を選択しました。[改訂フェーズ計画](ai-image-generation.md#改訂計画2026-10-14)が今後の作業方針です。以下は旧方式の評価記録であり、背景変更0画素の条件と局所合成の改善案は新方式へ引き継ぎません。

## Context

フェーズ1〜4で撮影、遮蔽補助画像、OpenAI編集、履歴比較を実装しました。人工背景による接続確認では、実写真の照明・境界・参照対応を判定できません。

評価設計・目視評価はAstra / high、評価用E2E実装は6.1sol / highです。画像生成側のモデルは既存の `gpt-image-2.5-sunburst` / `medium` を維持します。

## Decision

公開サンプルの実庭写真1枚と実植物写真2種類を使い、次の3ケースを各1回生成します。APIを呼ぶ前に撮影だけ実行し、対象が見えることと重なりを確認します。入力の[出典・利用条件](../e2e/fixtures/ai-quality/README.md)を付属させます。実寸は未測定で、ECの商品現物との一致は評価対象にできません。

| ケース | 主な確認対象 |
| --- | --- |
| single | 低木1個の根元・輪郭・葉の質感・接地 |
| multiple | 樹木1個と低木2個の個数、種類、参照の取り違え |
| overlap | 3D植物・家具の重なり、補助画像、家具の保護 |

客観的な必須条件は寸法一致、透過0、編集範囲外変更0、家具変更0、履歴・ダウンロードのバイト一致、庭JSON不変です。画像差分の外接矩形は植物輪郭の測定には使いません。膨張マスクの背景部分も変更されるためです。

目視では個数・大きさ・根元位置・参照の外観・前後関係・境界・照明を「許容／要修正／破綻／判定不能」で記録します。少数例の結果を一般的な成功率や品種判定の精度に読み替えません。

評価用のBefore、補助画像、参考写真、coverage、After、撮影snapshot、測定値を各ケースのフォルダーへ保存します。生成履歴の通常の保存形式は変更しません。課金するE2Eは2つの明示フラグが揃った場合だけ有効です。

## Alternatives

- 保存済みの259×194pxの利用者写真は、境界評価に解像度が不足し、検証成果物へ私的な写真を残すことになるため採用しません。
- 元写真に写る花壇・幹などの遮蔽は、撮影段階で制約を確認します。既知の入力不整合を追加の有料生成で繰り返し確認しません。
- 画質を見ずにマスクの拡張・影の編集・待機時間の延長を行いません。変更が必要な場合は画像上の根拠と保護範囲への影響を記録します。

## Consequences

背景の完全保持は自然な合成を保証しません。現在は3D配置同士の遮蔽に対応し、元写真の奥行きは解析しません。固定8pxの編集余白を超える葉や接地影は生成後の貼り戻しで切れる可能性があります。

### 前回の時間切れ

フェーズ4の時間切れは、WindowsのModern Standbyと一致しました。2026-10-14 12:31:06にLidを理由に休止し、12:33:10にキーボード入力で復帰しています。ブラウザー内のBefore表示は成功済みで、テスト側の受信が約130秒遅延しました。撮影操作は約1.49秒でした。処理やtimeoutの変更は行っていません。

証拠: `artifacts/phase5-occlusion-timeout-investigation.json`、`artifacts/phase5-occlusion-system-power-events.json`。

## 実行結果

### 結論（2026-10-14）

機能の確認と評価に基づく最小修正を実施しました。配置への追従は一部改善しましたが、実写真に自然に馴染む品質には達していません。

有料生成は基線3回と修正後1回の計4回です。全4画像が1280×853px、不透明で、編集領域外と家具の変更は0画素でした。APIへ送るBeforeと補助画像は庭写真との合成画像です。3D単体の切り抜きは送信していません。原寸1280×853pxに下だけ余白を付け、1280×1024pxで生成し、原寸へ戻しています。

| 実行 | 入力枚数 | 変更画素 | 生成待機の測定 | 統合検証 |
| --- | ---: | ---: | ---: | --- |
| 基線 single | 2 | 12,094 | 26,175ms | 履歴取得・PNGダウンロード・再読み込みまで成功 |
| 基線 multiple | 3 | 32,701 | 25,573ms | 同上 |
| 基線 overlap | 7（補助4） | 19,087 | 33,944ms（traceの通信時間） | HTTP200、画面の保存済み表示。検証ツール失敗後に画像を回収 |
| 修正後 multiple | 3 | 32,701 | 23,627ms | 履歴取得・PNGダウンロード・再読み込みまで成功 |

測定方法が異なるoverlapの時間を他の値と厳密比較しません。どの値も一般的な処理時間を保証しません。

### 目視品質

| ケース | 確認できた点 | 未達・判定不能 |
| --- | --- | --- |
| 基線 single | 低木1個、黄緑の密葉という参考の外観 | 卵形・平底の切り抜き感、接地が不自然 |
| 基線 multiple | 3個体と樹木／低木の区別 | 樹木の幹が太くなる、根元が上へ移動、樹冠の矩形状切断。低木も接地が不自然 |
| 基線 overlap | ベンチの画素保持、完全遮蔽の低木の不適切な露出は見られない | 樹冠上辺・左側の切断、根元ずれ。大きく隠れた左低木の個体保持は判定不能 |
| 修正後 multiple | 太い幹と根元のずれが改善、3個体と参考の外観を保持 | 樹冠上部の切断、低木2個の切り抜き感が残る。奥の低木の接地は特に要修正 |

庭写真は日陰・拡散光が中心です。強い直射光の投影影、正確な品種、実寸、成長段階、実商品との一致は評価できません。参考低木に写る壁・日付文字の転写は、4結果の目視では見られませんでした。

### 実装した修正

- `ai_service.py` の生成指示を、主画像の根元・幹幅・樹冠中心・見かけの大きさを優先する段落へ整理しました。参照の成熟木サイズ・背景・光・文字を転写せず、マスク余白は周囲の背景に戻すよう明示しています。自然な葉先と葉間を許し、滑らかなモデル輪郭をそのままなぞらない指示も追加しました。
- `AiImageGeneration.jsx` に、写真内の塀・植栽の前後関係は自動判定しないことと、配置・形・接地影の確認事項を表示しました。
- 評価用E2Eを撮影・生成・計測の責務で分け、実行別フォルダー、出典、入力順、Before、補助、coverage、マスク、After、撮影snapshotを保存します。再比較時には基線の配置を再使用し、生成前の画像一致を確認します。
- 大きなリクエスト時のChromium inspector cacheに依存しないよう、実生成POSTのHTTP状態、画面のAfterと保存済み表示、実履歴APIの画像バイトを照合する検証へ修正しました。APIの正常応答はモックしていません。

修正前後のmultipleはBefore・coverage・参考写真2枚のバイト列と入力順がすべて一致しました。証拠は `phase5-live-02/multiple/baseline-comparison.json` です。ただし各指示で1回の生成なので、確率的な出力のばらつきと指示変更の効果は分離できません。

### 検証ツールの失敗と回収

基線overlapの実POSTは19,974,245bytes、HTTP200、応答本文3,047,872bytesでした。Playwrightの`response.json()`で`Request content was evicted from inspector cache`が発生しました。最初の画面遷移以外にnavigation/reloadの記録はありません。大きなリクエストの寄与は推測です。

traceのDOM snapshotからAfter PNG 2,285,512bytesを追加生成なしで回収し、保護画素を再計算しました。元のE2Eは失敗扱いを維持します。このケースの履歴直接取得・ダウンロードのバイト一致・生成後の再読み込みは未確認です。修正後harnessはmultipleで成功しましたが、同じ大きなoverlap条件の有料再実行は行っていません。

### 写真由来の遮蔽

右前景の花壇・白い縁取りを手前へ残し、その背後へ低木を置く意図で無課金撮影しました。Beforeでは植物が前景へ上描きされました。これは想定した前後関係を保持できない制約の確認です。写真から測定した物理的奥行きの正解を示すものではありません。

### 次の改善課題

まず既存画像を使い、元の植物領域はAfterを保持し、外側8pxの余白だけを背景へ遷移させる局所合成を無課金で比較できます。ただし一律に輪郭をぼかすと旧3Dモデルが透ける恐れがあり、切れた樹冠自体も復元できません。

次回の生成評価では合成前の出力も取得し、生成と貼り戻しのどちらで破綻したかを分離することが優先です。その根拠に基づき、主画像上の各植物の根元・樹冠範囲を数値で対応付けること、輪郭が許可範囲で切れたことの検出、品質不良時の結果の扱いを設計します。写真前景の保護は、別途手動指定などの方式選択が必要です。

これらは追加設計の課題であり、今回実装した機能ではありません。Astra / highで設計判断、6.1sol / highで実装・回帰確認を行う分担を継続します。

参照役割と変更／保持条件を明示する方針は[OpenAIの画像プロンプトガイド](https://developers.openai.com/api/docs/guides/image-prompting)を参照しました。実測の品質判定は本プロジェクトの出力に基づきます。

- 開発用・E2E用とも、既存の庭・写真・配置・履歴のハッシュが開始前と一致しました。検証用の庭・履歴は残っていません。`phase5-db-before.json` と `phase5-db-final.json` に記録しています。
