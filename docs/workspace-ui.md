# 庭エディタの画面構成と自動保存

## Context

庭の編集は、写真を読み込み、庭の輪郭と実寸を決め、商品を配置する順で進む。作業面を広く取り、写真・辺・カメラ・配置物の操作を、その対象の近くに置く必要がある。保存は全体スナップショットで行い、各ポインター移動からAPIを呼ばない。

## Decision

### 庭一覧

- 「新しい庭をつくる」で、既存の庭と重ならない既定名（「新しい庭」「新しい庭 2」…）の庭を作る。名前は編集画面の「庭の名前を変更」で変える。POSTで寸法を省略するとAPIが幅10m・奥行き8mを設定する。
- 庭カード右上の三点ボタンから「複製」「削除」を開く。外側のクリック、Escape、フォーカスが外れたときに閉じ、同時に開くメニューは一つにする。削除は確認ダイアログを通し、取消後は三点ボタンへフォーカスを戻す。複製は[庭の複製](garden-duplication.md)を参照。

### 編集画面の構成

- 上部は共通ヘッダー（[共通ヘッダー](decisions/shared-site-header.md)）だけにする。ヘッダーのリンクも未保存確認を通す。
- 作業面の上の1行に、「← 庭一覧」、庭名と「庭の名前を変更」、保存状態、写真／3Dの切替、3D表示の視点操作（「上から見る」「初期視点」、写真のない庭だけ「土台設定」）、右パネルの開閉を置く。保存状態はアイコンとツールチップ、読み上げ用の状態通知で示す（「保存済み」「自動保存待ち」「保存中…」「輪郭を描画中」「施工範囲の修正が必要」「保存できませんでした」）。保存ボタンはない。
- 新規作成、直接アクセス、一覧からの再入場、再読み込みは、写真の有無にかかわらず写真＋設計で開く。写真なしは写真のアップロード枠を表示する。同じ庭を開いている間の手動選択は、保存応答や再取得でも維持する。選択した表示は画面内の状態で、API・GardenDocument・DBには保存しない。
- 写真の操作は表示領域右上のツールバーに置く。並びは「配置」／「輪郭と寸法」の切替（入力済みの辺の数を表示）、写真を変更・写真を外す、地面・グリッド・配置物の表示切替。アイコンは lucide-react に統一し、アイコンだけのボタンには操作名を `aria-label` と `title` で付ける。輪郭の描画中は写真の上に帯を出さず、同じツールバーに、操作の説明を出す i、置いた点の数（「1/64」）、元に戻す矢印の「戻す」（最後の点を戻す。点が無いときは押せない）、×の「取消」（輪郭の描画を取消）だけを置く。操作の説明は i にホバーするか、フォーカスしたときだけ出す。描画中は写真をツールバーの下に下げ、ツールバーで写真の角を覆わない（覆うとその下に点を置けない）。
- 「輪郭と寸法」では、帯に入力済みの辺の数、パースの求め方、面積・外周、「庭の領域を書き直す」「完了」を出す。辺の長さは写真上の辺をクリックし、辺の近くの非モーダルパネルで入力する（[写真上の辺の計測](polygon-edge-editing.md)）。
- 配置物を選択すると、同じツールバーに3D表示では「移動」「回転」「拡縮」、両方の表示で「削除」を出す。回転は[回転リング](rotation-ring.md)を使う。操作は背面へ伝えない。Delete／Backspaceで選択中の配置物を削除し、入力欄・ダイアログでのキー操作は背面の配置物へ伝えない。
- 右パネルは「買い物リスト」（初期表示）と「商品一覧」のタブで、左右キー・Home/Endで切り替える。商品一覧の商品、買い物リストの行を庭の地面へドラッグして配置する。配置済みの一覧は商品一覧のタブにあり、行のクリックで選択する。パネルは幅280〜560pxでドラッグして変えられ、幅はブラウザーに保存する。内容は[庭の買い物リスト](garden-shopping-lists.md)を参照。
- ECの商品画面から`?productId=...`で開いたときは、その商品のモデルを選択状態にし、利用者が地面をクリックするまで配置しない。Escで選択を解除する。
- 庭写真が未アップロードの庭には、クリック・ドラッグのどちらからも新しく配置しない（[配置範囲](placement-bounds.md)）。写真のある庭では、輪郭と実寸範囲が確定するまで3D庭へ切り替えられない。
- 完成イメージとAI生成は、表示領域右下の「完成イメージ」の1つのボタンから開く（[完成イメージとAI画像生成](image-studio.md)）。
- 操作説明の帯は表示しない。モデルの読み込み状況だけを画面外の状態表示として残す。
- 土台寸法、削除確認、未保存確認には共通のDialogを使う。ネイティブdialogをportalで表示し、背面を操作対象から外す。Tabの移動範囲、Esc、初期フォーカス、呼び出し元への復帰を揃える。削除・未保存の確認では取消側に初期フォーカスを置く。処理中の削除は閉じる操作を無効にする。

### 土台の寸法

- 写真のない矩形の庭は、3D表示の「土台設定」から幅・奥行き（各辺1〜50m）を変える。「土台に適用」で編集中のGardenDocumentへ反映し、自動保存する。Escで閉じたとき、未適用の入力は破棄するが適用済みの寸法は維持する。
- 原点を中心に外枠を変更し、配置物のID・位置・回転・倍率を維持する。配置基準点が範囲外になる縮小を拒否する。
- 写真のある庭では、各辺の実寸を写真上の辺で入力する。
- 保存中、3D変形中、写真の輪郭描画中は寸法を変更できない。

### 自動保存

- 有効なGardenDocumentの変更が500ms落ち着いたら、全体スナップショットを非同期にPUTする。配置・寸法・写真・輪郭・辺の長さ・庭名のすべてが対象。写真の未確定輪郭、配置ドラッグ中、範囲外の配置がある間は送信しない。
- 保存要求は同時に1件だけ。送信時のdocumentと現在値の同一性を比較し、保存中に新たな編集があれば編集内容は保持してrevisionだけを引き継ぎ、次の保存へ送る。保存中も編集を続けられる。
- 通信障害・409競合は表示して自動の再送を止め、編集中の値を残す。再試行は画面の「再試行」で行う。ログインの期限切れは[編集中のログイン期限切れ](session-expiry-edits.md)を参照。
- アプリ内の移動（庭一覧、ヘッダーのリンク、ECへの移動）は、進行中の保存と追加編集の保存が完了してから行う。輪郭が未確定・保存できない写真のときは、保存せずに戻るかを確認する。ブラウザーの終了／再読込は完了を保証できないため、未保存時の離脱警告を出す。

## Alternatives

- すべての操作を右側へまとめる案は、写真上の辺との対応が離れ、素材選択と変形が競合する。
- 表示切替をメニューに畳む案は、操作が1段深くなるため採用しない。
- 写真の有無で初期表示を変える案、前回の表示を保存する案は採用しない。写真から設計を始める順序に合わせ、毎回写真＋設計で開く。
- 保存ボタンを残して配置だけを自動保存する案は、写真・寸法が保存されないため採用しない。
- 縮小時に配置物を自動移動・拡縮する案は、既存の設計を意図せず変えるため採用しない。

## Consequences

写真・多角形・カメラ・配置物のGardenDocumentとMySQLの構造は変わらない。表示の切替だけでは庭のPUTは起きない。写真なしの庭で土台設定を行う場合は3D庭へ切り替える。配置数量の確認とEC連携は右パネルの買い物リストが担う。3D表示では面積・外周を表示しない。

デスクトップ用画面を対象にし、狭い幅でも操作同士が重ならないように折り返す。スマートフォン専用UIは対象外。

旧写真で未設定の `calibration` / `projectionSize` がnullとして出力され、旧データのJSON比較が失敗する互換性の問題があったため、Pydantic Fieldの `exclude_if` でこの2項目だけ未設定時に省略する。入力の省略／nullは引き続き受理し、庭本体の `photo: null` は従来どおり出力する。

E2Eは `e2e/workspace-ux.spec.ts`、`e2e/editor-autosave.spec.ts`、`e2e/editor-default-view.spec.ts`、`e2e/garden-dimensions.spec.ts`、`e2e/garden-menu.spec.ts`、`e2e/editor-toolbar.spec.ts` にある。
