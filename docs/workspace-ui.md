# 庭エディタの画面構成

## Context

2026-10-02。従来の左右サイドバーと二段ヘッダーが作業面を圧迫し、写真・辺・カメラ・配置物の操作が離れていた。要求は、装飾を増やすことではなく、庭を編集する順序に合わせて画面とポップアップを再設計し、既存の保存・編集動作を維持すること。

## Decision

- 上部1段に、一覧へ戻る操作、庭名、寸法情報、未保存状態、保存を集約する。ロゴから戻る場合も未保存確認を通す。
- 写真／3Dの切替と、その表示に必要な操作を作業面の上に配置する。キャンバスは残りの高さと幅を使い、通常のPC画面ではページ全体をスクロールせず編集する。
- 素材カタログは下部の横並びトレーへ移す。種類と寸法を見て配置でき、同種の連続配置を維持する。Escで配置モードを解除する。
- 右の「配置と編集」は、選択した配置物の変形、配置一覧の順で表示する。カタログと独立して開閉でき、閉じた分だけ作業面を広げる。
- 多角形の長さは辺の近くの非モーダルパネルで入力する。入力欄を初期選択し、Enterまたは適用で庭全体の縮尺を変更する。写真上の輪郭・配置物の接地位置を保つ。取消・Escは未適用の入力を破棄する。ResizeObserverでポップアップと写真領域の大きさを測り、領域内に位置を調整する。
- 土台寸法、カメラ設定、削除確認、未保存確認には共通のDialogを使う。カメラ設定は写真と基準点を左、実測値と計算結果を右に配置し、適用／取消は下部に固定する。
- ネイティブdialogをportalで表示し、背面を操作対象から外す。Tabの移動範囲、Esc、初期フォーカス、呼び出し元への復帰を揃える。削除・未保存の確認では取消側に初期フォーカスを置く。処理中の削除／カメラ計算は閉じる操作を無効にする。
- 共通色・フォーム、作業面、写真、ダイアログ、一覧のCSSを分ける。SVGのアイコンと素材図はコード内で定義し、外部フォント・画像・UIライブラリは追加しない。

## Alternatives

- 既存3列の余白・色だけを変更する案では、作業面と操作位置の問題を解消できない。
- すべての操作を右側へまとめる案では、写真上の辺との対応が離れ、素材選択と変形が競合する。
- キャンバス全面を覆う常設フローティングパネルは、写真の頂点や配置操作を遮る。常設パネルは作業面の外に置き、辺の計測だけを局所表示にする。

## Consequences

写真・多角形・カメラ・配置物のGardenDocumentとMySQLの構造、Three.jsの座標・透視投影・配置ルールは維持する。土台設定などのモーダルを開いている間は、閉じてから保存や庭の配置に戻る。写真モードでは数値で変形するため、3D専用ハンドルの切替ボタンを表示しない。

全E2Eで、以前追加された未設定の `calibration` / `projectionSize` がnullとして出力され、旧写真のJSON比較Lが失敗する互換性問題を検出した。旧データの期待値は変更せず、Pydantic Fieldの `exclude_if` でこの2項目だけ未設定時に省略する。入力の省略／nullは引き続き受理し、設定済みの値は維持する。庭本体の `photo: null` は従来どおり出力する。DBマイグレーションは不要。

デスクトップ用画面を対象にする。カタログは狭い幅で横スクロールし、ダイアログは画面高さに合わせて内容部分がスクロールする。スマートフォン専用UIは今回の対象に含まない。

## 検証

実FastAPIと専用MySQLを使用するChromium E2Eを利用する。

- 既存A〜R：作成、配置、ドラッグ、回転、拡縮、複製、削除、通信失敗と再試行、競合、GLB再読込、写真輪郭、カメラ校正、寸法、辺計測、保存・復元。
- S：カタログと編集パネルの独立開閉、1280×800の作業面、配置終了のEsc、未適用寸法の取消、Tabの循環、Deleteの背面伝播防止、未保存確認とフォーカス復帰、削除確認の取消。
- R：1024×768で辺の計測表示が写真領域内に収まること、マウス・Enter・Spaceでの選択と閉じる操作・Escでのフォーカス復帰、計測とカメラ設定の取消で庭JSONが変わらないこと。

再読み込み後の画面とAPI JSONは `artifacts/e2e/workspace-reloaded.png` / `.json`、辺とカメラ設定は `workspace-edge-1024.png` / `workspace-camera-dialog.png`、削除確認は `workspace-delete-dialog.png`。途中で検出したフォーカス不具合のtraceは `workspace-first-failures/` と `workspace-focus-failure/` に保持する。

2026-10-02の最終実行：`npm run precheck`、`npm run build:web` は成功、`npm run test:e2e` は20件すべて成功（1.8分）。旧写真の互換性失敗時のtraceは `workspace-legacy-failure/` に保存した。開発用APIとWebを再起動し、8080/5173のHTTP 200とChromeでの表示も確認済み。実写真の撮影精度については、このUI検証の対象外。

## 2026-10-13: 庭一覧のオプションメニュー

庭カード右上の三点ボタンから「複製」「削除」を開きます。外側のクリック、Escape、フォーカスが外れたときに閉じ、同時に開くメニューは一つにします。削除時の既存の確認ダイアログは維持し、取消後は三点ボタンへフォーカスを戻します。複製は既存APIで別IDとして保存し、配置物のIDも新しくします。実API・専用MySQLで元の庭の保持、複製の保存と再読込、取消、削除、1440/390/320pxの表示を `e2e/garden-menu.spec.ts` で確認します。

## 2026-10-13: 計画操作を庭名バーへ統合

「数量・施工範囲」「植物候補を相談」「完成イメージを確認」「配置したものから商品を探す」「ECへ戻る」を庭名・保存状態・保存ボタンと同じdocument-barへ移しました。独立した操作バーを削除し、PCでは64pxのバー内にまとめます。1100px以下では同じバー内で折り返し、保存ボタンと状態表示を一組に保ちます。旧bodyの1120px固定最小幅を撤廃し、中間幅の横はみ出しも解消しました。

既存の計画ダイアログ、数量編集、完成イメージ、未保存の保存確認、API保存を維持します。`e2e/editor-toolbar.spec.ts` と通常ブラウザーの `artifacts/e2e/editor-toolbar-normal-*` でPC・中間幅・スマートフォンを確認します。通常ブラウザーは既存の50本の木がある庭を読み取り、ダイアログの開閉と画像生成を確認します。庭データの変更・保存は専用E2E用の庭だけで行います。


## 2026-10-13: 描画内ツールバーと商品サイドバー

配置物の編集は描画領域右上のObjectToolbarへ移した。3Dでは移動・回転・拡縮を切替でき、詳細メニューで位置・角度・倍率・角度リセット・複製・削除を操作する。写真でも詳細編集を利用できる。詳細は外側クリックまたはEscapeで閉じ、Escapeではトリガーへフォーカスを戻す。操作は背面へ伝播させず、詳細領域は描画領域の高さに合わせてスクロールする。

右パネルは商品候補／カート内容のタブとなり、左右キー・Home/Endで切替可能。初期表示は商品候補。配置物一覧は商品候補の下で維持する。右パネルを閉じても編集ツールバーを利用できる。ヘッダーのECカートリンクとサイドバーは同一カートを参照する。旧Decisionの「常設パネルは作業面の外」は、選択中のみ表示する小型ツールバーと開閉可能な詳細メニューについて置き換える。

### 2026-10-13 追加調整

- 写真の通常表示ではカメラ状態と操作説明の案内バーを表示しません。輪郭描画中の進捗は維持します。
- 庭右上の「詳細」は未選択時も表示し、その中の「数量・施工範囲」に面積・外周・配置素材の集計をまとめます。数量は表示専用です。
- 数量は素材の追加・複製・削除に応じて更新され、ECカート数量とは独立しています。
- 上部の「ECへ戻る」ボタンは削除し、ECトップへの移動は共通ヘッダーのロゴから行います。未保存確認は維持します。
- 保存状態は保存ボタンの文言に統合します。通常は「保存」、処理中は「保存中…」、完了後は「保存済み」とし、失敗時は再試行を表示します。
- 写真／3Dの表示切替は庭描画幅の中央へ配置し、狭い画面では右側の視点操作を別の行にします。

## 2026-10-21 表示領域右上のツールバーへの集約

- Context：写真の上に操作の帯（写真のカメラ設定・領域の書き直し・写真を外す・表示切替）があり、表示領域の高さを圧迫していた。右上の「詳細」には数量・施工範囲と「この数量で商品を探す」があり、未選択時も開けたが、配置数量は右パネルの買い物リストと重複していた。下端の操作説明（「オブジェクトを選択して編集」等）と「1目盛り = 1m」も常時表示されていた。
- Decision：写真の操作は表示領域右上のツールバーへ移し、写真の上の帯を廃止する。並びは「配置／輪郭と寸法」の切替、写真を変更・カメラ設定・写真を外す、地面・グリッド・配置物の表示切替、「詳細」。アイコンは lucide-react に統一し、アイコンだけのボタンには操作名を `aria-label` と `title` で付ける。「詳細」は配置物を選択した時だけ表示し、位置・回転・倍率・複製・削除だけを持つ。数量・施工範囲と「この数量で商品を探す」は削除する。面積・外周は「輪郭と寸法」の帯に表示する。下端の帯は削除し、モデルの読み込み状況だけを画面外の状態表示として残す。
- Alternatives：表示切替をメニューに畳む案は、操作が1段深くなるため採用しない。数量を詳細に残す案は、買い物リストと同じ情報を二か所に持つため採用しない。
- Consequences：配置数量の確認とEC連携は右パネルの買い物リスト（[庭の買い物リスト](garden-shopping-lists.md)）が担う。旧「この数量で商品を探す」が作っていたECの資材ページへの遷移（`canvas-items`）はなくなる。3D表示では面積・外周を表示しない。
