# 植物サイズ保持：編集マスクの余裕を除く変更

後続の判断：[植物サイズ制御方式の判断](ai-size-control-decision.md)。現行方式の追加調整を止め、サイズ要件を維持する場合は専用の構造条件を使う全景生成方式の適合性調査を推奨します。サイズ差の許容は利用者の判断事項です。追加生成は行っていません。

2026-10-16。前回の候補指示でも単体の低木は約1.4倍に拡大しました。主画像・補助画像の拡縮や座標の移動、出力の拡縮という実装上の不整合は確認できませんでした。今回は指示や参考写真を変えず、編集マスクの余裕だけを8pxから0pxへ変更して確認します。

結果：評価用変更の実装と検証は完了しましたが、サイズ保持の修正は未達です。実生成1回で幅約1.5倍の拡大が残ったため、通常利用へ適用せず停止しました。重なりの追加生成は0回です。

## Context / Decision

従来の`editable_mask`は植物の信号を周囲8pxへ広げ、家具信号を除いていました。単体の植物の画素範囲は100×109px、余裕付きマスクは116×125pxです。これは境界の自然さを確保するための余裕であり、不具合が確定したという意味ではありません。今回の仮説は、編集対象を植物の元の画素に絞ることで拡大を減らせるかというものです。

公式仕様ではマスクはモデルへのガイドであり、厳密な形状保持を保証しません。余裕を除くだけでサイズ保持が直るとは断定しません。[OpenAI公式画像生成ガイド](https://developers.openai.com/api/docs/guides/image-generation#edit-an-image-using-a-mask)

`AiSettings.mask_margin_px`を追加し、通常は従来の8px、実評価だけ0pxを選べるようにしました。評価用上書きにはe2e、二重実生成フラグ、明示quality、マスク使用、実行計画、証拠保存先が必要です。0または8以外は拒否します。HTTP要求・画面・DB形式に選択項目は追加しません。

`editable_mask`は余裕0の場合に植物の元の信号だけを使います。赤信号が2を超える画素を対象とし、家具の緑信号が2を超える画素は引き続き保護します。右・下の余白も編集対象にしません。AfterはAPI出力全体から余白だけを除き、元写真への貼り戻しや出力の拡縮を加えません。

評価用コマンドは`--mask-margin-px 0`を受け付けます。まず旧基線の入力・マスク・指示を検証した後、選択した余裕幅のマスクを作ります。入力画像・候補指示・モデル・medium・寸法・画像順を固定し、マスクだけが変更されたことを確認します。実送信前の照合と証拠にも`maskMarginPx`を追加しました。旧計画の8pxとの互換性を維持します。

## 検証手順と上限

位置精度は利用者が現状で許容済みです。今回も厳密な位置・背景点測定を合否条件にしません。目立つ拡大、旧3Dの輪郭の残り、植物の欠落や家具の変形、自然な境界と接地を確認します。

単体を1回生成します。目立つ拡大・境界の破綻がなくなった場合だけ重なりを1回生成します。上限2回、再試行・自動再生成は0回です。不合格・判定不能・通信や後処理の失敗で停止し、未検証の候補を通常利用へ適用しません。

独立検証は、実モデルの出力では確実に再現できない条件を対象とします。余裕0の編集可能画素が植物信号だけであること、家具と余白の保護、既定8pxの互換、不正な設定と実送信条件の不一致拒否を明示した画像・計画で確認します。実際の生成・保存・表示は実API/MySQL/Chromiumで確認し、正常応答をモックしません。

事前計画は`artifacts/e2e/ai-quality/mask-margin-review-plan.json`です。新しいrun名で登録し、過去の出力・マスク・計画は上書きしません。

## 実行結果

単体を1回生成しました。元の画素範囲100×109px、8,494画素だけが編集可能となり、マスクを周囲へ広げていないことを実送信証拠で確認しました。入力画像・参考写真・指示全文・品質・モデル・寸法は前回候補と一致し、変更されたのはマスクだけです。

生成後の植物の外形は原寸の概測で`[571,494,718,622]`、幅約147px、高さ約128pxでした。旧目視基線99×107pxに対して幅約1.48倍、高さ約1.20倍です。各端点に±5px程度の読み取り誤差を見込みます。1枚ずつの出力なので高さの違いをマスク変更の効果と断定できません。幅の明らかな拡大は残っています。

通常の既定指示v1、マスクの余裕8pxを維持しました。これは通常設定が品質合格という意味ではありません。0pxの設定は評価専用として残します。目立つ拡大が残るため重なりを生成せず、今回の課金要求は1回、再試行0回です。位置精度は不合格理由にしていません。

## Consequences

今回の変更でサイズ保持が直ったという結論にはできません。マスクの余裕を除くことだけでは、この入力の拡大を防げませんでした。指示の整理・quality比較・今回のマスク変更で未達が続いているため、同じ調整の再生成を自動で繰り返しません。

次はAstra / highを担当設定とするサイズ制御方式の判断です。API出力全体を採用する条件で、サイズの許容範囲をどう扱うか、別方式が必要かを判断します。元写真への貼り戻し・3D単体の切り抜きへ無断で変更しません。担当設定はこのチャットの実行モデルの切り替えを証明するものではありません。
